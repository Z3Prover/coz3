Z3 commit message: Fix union normalization in symbolic derivatives (#10920)

## Summary

Use `seq_rewriter::mk_union` when rebuilding reduced unions and
normalizing reversed unions in the symbolic derivative engine.

`derive::mk_union_core` already flattens unions and applies its existing
reductions, but its final loop called the raw `seq_util::rex::mk_union`
constructor. That preserved insertion order and built left-associated
trees, bypassing the general rewriter's operand ordering and
right-associative normal form. Equivalent union presentations could
therefore produce different residual ASTs and multiply the work of
structural state deduplication.

The reversal helper had the same bypass. Its unnormalized union can
survive beneath a star in the derivative's continuation, so normalizing
only the derivative's outer union does not cover it.

The production change consists of two constructor calls. It retains the
existing reductions and reuses the smart constructor rather than
introducing another normalization implementation.

## Regression coverage

The new tests check commutativity, associativity, and idempotence of
derivative unions against the smart constructor's normal form, for both
Antimirov and Brzozowski derivatives. They also cover symbolic
Brzozowski cofactors, complement-aware operand ordering, the
nullable-concatenation rule, and reversal of a starred union with the
union retained in the derivative's continuation. Multi-character
residuals prevent character-range collapsing from masking an incorrect
union shape.

The main-builder regression fails before the first constructor change.
With only that change, the reversal regression still fails; both pass
after the two changes.

The following native test modules pass with the change:

```text
test-z3 /seq seq_regex_bisim seq_rewriter seq_regex_witness
```

No equivalence-study counters, algorithm-selection controls,
loop-compaction rewrites, or universal-prefix rewrites are included in
this patch.
