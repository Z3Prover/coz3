Z3 commit message: nseq: consume seq_monadic as a decision procedure, not a branch enumerator

nseq trails theory_seq on the regex corpus (1409 vs 1430 of 1476 files, T=10)
even though it is the stronger word-equation engine: strip monadic
decomposition from theory_seq and it falls to 1184, well below nseq.  Of the 36
files theory_seq decides and nseq does not, 29 are lost by that same ablation --
the deficit is one missing integration, not an algorithmic gap.

Both theories already share seq_monadic, but through different interfaces.
theory_seq uses it as a decision procedure -- add/check/core/materialize, with
l_undef a first-class answer -- and gains 246 files.  nseq used only iterate(),
consuming the engine's internal DFS branches, which recovers 6 of the 36 and not
one of the 20 sat files: a branch enumerator can refute, but it cannot hand back
a model.

Add apply_monadic_leaf, which calls the same component the way theory_seq does.
It fires on an equation-free node whose memberships are all covered, so a
verdict about the memberships is a verdict about the node:

  l_false -> close the node, explained by the engine's minimized core.
  l_true  -> child A pins every token to the witness word by a str_eq; child B
             is the node unchanged.  Child A is a restriction, so it is sound as
             one disjunct whatever the witness is worth -- nseq substitutes and
             validates it itself, trusting the engine with nothing -- and child B
             alone covers the parent, so completeness does not depend on the
             witness being right.
  l_undef -> fall through, node untouched.

Child B needs is_signature_alias: it is an exact clone, so without the exemption
the sibling loop-cut would close it against its own parent and leave the node
decided by one witness -- a spurious UNSAT -- and the rule would re-fire down an
N -> B -> B_B spine.

Two configuration points earn the result.  The engine's intersection refinement
is off by default while theory_seq sets 10; these nodes are an intersection by
construction, so without it the engine bails on exactly the re.inter/re.comp
shapes the rule targets.  And the call is budgeted, unlike theory_seq's
1000000: theory_seq calls at final check with nothing cheaper left, whereas this
rule calls mid-search ahead of nseq's own rules, so an expensive decision is
taken instead of a possibly cheap search step.  One file nseq closes natively in
0.10s costs the engine ~6s to decide (theory_seq needs the same 6s on it).
Unbounded the rule loses 4 files to that preemption; at 300000 it loses none.

Measured on the regex corpus (1476 files, T=10), smt.nseq.monadic_leaf=true:
nseq 1409 -> 1433, +24 gained (15 sat, 9 unsat), 0 lost, 0 contradictions,
commonly decided set 15.8% faster.  All 15 newly-sat files pass model_validate;
test-z3 /a 99/0.

Head to head, nseq now edges past theory_seq (1433 vs 1430) instead of trailing
it by 21, and the two stay complementary: of the 33 files they disagree on,
nseq's 18 are 15/18 unsat and carry the equation- and length-bearing families,
while theory_seq's 15 are half sat and sit in the pure-membership families.
Zero contradictions; virtual best 1448.

Off by default (smt.nseq.monadic_leaf, budget smt.nseq.monadic_leaf_budget).
